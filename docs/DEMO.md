# DEMO — сценарій показу BlowMyJob (2 хвилини)

Ціль: показати один наскрізний сценарій **онбординг → свайпи → профіль → інсайти** за 2 хвилини (максимум 3).
Після демо ~2 хвилини запитань: короткі відповіді — у розділі «Запитання» нижче.

## Підготовка (до початку захисту)

1. Запустити застосунок за інструкцією з [`README.md`](../README.md#-запуск-run) і перевірити, що `.env` містить `GEMINI_API_KEY`.
2. Відкрити http://127.0.0.1:5000 у **двох** вікнах браузера:
   - **вікно A (основне)** — порожня сесія (приватне вікно) для живого онбордингу;
   - **вікно B (запасне)** — профіль, який уже пройшов онбординг із `docs/demo_cv.txt`, із 2–3 вподобаними вакансіями.
   Якщо Gemini недоступний під час демо, одразу переходимо у вікно B.
3. Мати під рукою файл [`docs/demo_cv.txt`](demo_cv.txt) (вигаданий CV Python-розробника).
4. Закрити зайві вкладки, увімкнути демонстрацію екрана, масштаб браузера 100 %.

## Запитання (коротко)

- **Чому статистика не з вакансій?** Зарплату вказано лише в ~16 % вакансій, і це пропозиція роботодавця; опитування DOU — фактичні зарплати десятків тисяч людей.
- **Де JavaScript і чи це не бізнес-логіка?** Лише анімація свайпу, панелі та запит на сервер. Ранжування, фільтри, збереження й розрахунки — Python.
- **Чому вакансія не повторюється?** ID свайпнутих вакансій передаються в ранжування як виключення.
- **Що, якщо для профілю мало даних в опитуванні?** Фільтр автоматично розширюється до мінімальної вибірки 30 відповідей.
- **Звідки дані та ліцензії?** Див. `docs/DATA_NOTES.md` і `data/sources.json`.

Детальний опис архітектури та алгоритмів для підготовки — у файлі «BlowMyJob: опис проєкту для захисту» в Slack-каналі команди.
